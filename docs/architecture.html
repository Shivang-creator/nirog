VECTOR INDEX complaint_embedding_idx

(patient_id, embedding vector_cosine_ops)

patient_id as prefix — C-SPANN descends one patient's span, so latency follows one history, not the clinic's size. A query that cannot say "search everyone" cannot accidentally do it.

Cosine, not L2. Titan does not guarantee unit norm; under L2 a long complaint drifts from a short one meaning the same thing.

Cut-offs per embedding space: 0.85 Titan / 0.55 offline. Distances across spaces are not comparable.

Three CockroachDB tools, all load-bearing · the rules require two

① Distributed Vector Indexing

The recall path itself — the index above, carrying 2,230 complaints. Honest note: at demo scale the optimizer prefers a scan over four rows and is right to; npm run db:explain prints both plans and we did not add an index hint to make the demo look better.

② Cloud Managed MCP Server

Claude Code connected read-only to the live cluster. Reading real query plans through it produced two corrections: the index had been built on (embedding) alone with patient_id filtered after the search; and an IS NOT NULL guard was hiding that unembedded rows sorted as perfect matches at the top of a doctor's screen.

③ ccloud CLI (agent-ready)

Backs npm run cluster:status — topology and the Cloud audit log as JSON. recall_event records every read of a patient's history; the control-plane log records every administrative action against the cluster holding it. A system asking doctors to trust its memory should answer both.

Deterministic core — no model touches this · the embedding finds candidates; a fixed rule decides what they mean

resolveRegion()

"the ache is back again" names no body part — back there means returned. Read alone it is unclassifiable. Read against what this patient said in July it is obviously lumbar. Memory supplies the region and region_source records that it was inherited, so a doctor can see the link was inferred.

recurrence rule

≥ 3 separate visits naming one body region within 90 days. Arithmetic, no scoring — a doctor can check it on paper in ten seconds.

It counts visits, not complaints: three sentences in one appointment are one presentation, and counting complaints would let a talkative patient trip the flag on day one.

SBAR assembly

Every field built from rows. An earlier plan had gpt-oss rewrite it into prose — but a model smoothing "the ache is back again" into "recurrent lumbar pain" invents a claim the patient never made, and how somebody describes their own pain is itself clinical information.

What the clinician reads · assembled from rows, never generated

Recurrence banner

"Why did you flag this?" is answered with a list of dates, not a similarity score. Meera has one complaint and comes back clean; Priya returns watch, not recurrence — a tool that only ever finds patterns is not detecting anything.

SBAR handover

The same rows ARIA heard, in the form a doctor reads. Assessment reads NOT ASSESSED — not "no history" — when memory was unreachable.

The degradation contract — cross-cutting
Every memory read returns MemoryOutcome{ ok, value, degraded, reason }, never a bare array, so it is impossible to consume a result without handling the case where memory was down. A failed lookup is never an empty list: "no prior complaints" and "could not check" would render identically, and a doctor reads that absence as reassurance. Absence of evidence is not evidence of absence — and an agent that cannot tell the difference should not be near a patient. The wording is asserted in the test suite, because here the wording is the safety property.
